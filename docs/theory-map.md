# Evidence for the plan-first human doc rules

Premise: AI writes far more than a person can read. Attention is a budget: every section must be able to change the reader's judgment, or it gets deleted (Simon 1971).

| # | Rule | Basis | Source |
|---|---|---|---|
| 1 | Heading text and order are fixed: "you always know where to look" | Label every block of information and apply the same principles to all blocks; headings help readers predict what follows; a repeated layout becomes a schema, so finding things stops taking effort | Horn 2001, SIGDOC Lifetime Achievement Award speech; ISO 24495-1:2023 Principle 2 (findable); Sweller 1988 |
| 2 | Headings do not contain answers | A label says what type of block this is, and the answer goes inside the block; one block covers one point | Horn 2001 (relevance, labeling) |
| 3 | No HTML, anchors, or tables; say each thing only once | Material that must be cross-checked back and forth adds load (split-attention effect); so does repeated information (redundancy effect); remove extraneous material (coherence principle) | Chandler & Sweller 1991; Mayer & Moreno 2003, *Educational Psychologist* 38(1) |
| 4 | "What this does" gives each feature's purpose and "When done", then one shared "Not doing" at the end | Commander's intent states only the purpose, the key tasks, and the end state, so the people carrying it out can act without asking; when one task has several features, each feature is a key task with its own end state | ADP 6-0 (2019) |
| 4a | When there are several features, each gets a number; later sections say "feature N"; dependencies go after the feature name | Chunks must be consistent and one thing must have only one name, so readers can match items across sections | Horn 2001 (chunking, consistency); ISO 24495-1 Principle 3 (understandable), the "consistent document" item |
| 5 | "When done" lists results the user can check and covers all completion criteria | The third level of situation awareness is projection: people need to know what state the system will be in when the work is done | Endsley 1995, *Human Factors* 37(1) |
| 6 | No Risks section; before writing, each risk goes into one of three places | Values the computer can calculate should also be monitored by it, with alarms; a screen full of red lights only confuses people. An estimated 85% to 99% of hospital alarm signals need no clinical intervention, so clinical staff become desensitized and may silence alarms or change alarm settings (warnings should be few). Whether people heed a warning depends largely on its design: users clicked through 70.2% of Chrome SSL warnings, only about a third of Firefox SSL warnings, and only about 9% to 23% of malware and phishing warnings (warnings belong at the specific decision) | Bainbridge 1983, *Automatica* 19(6): 775-779; Joint Commission, Sentinel Event Alert Issue 50 (2013-04-08); Akhawe & Felt 2013, USENIX Security |
| 7 | Risks known only during execution become stop conditions in the plan doc | Many false alarms make people abandon automation; once people are out of the loop, they take over slowly when something goes wrong | Parasuraman & Riley 1997; Endsley & Kiris 1995 |
| 8 | Only three kinds of decisions go to the user; conventions go into the rules | One-way doors need care, two-way doors need speed; using a heavy process for two-way doors leads to slowness and excessive risk aversion | Bezos 2015 letter to shareholders (SEC 8-K Exhibit 99.1) |
| 9 | Each decision is marked "can undo" or "hard to undo"; hard-to-undo ones state the cost | Only after telling which kind of door it is does a person know how much attention to spend | Bezos 2015 |
| 10 | The human doc covers only the four things (no execution steps) | The operator can judge only at a meta level whether the computer's decisions are acceptable, and showing target values helps most; the main difficulty in code review is understanding what a change results in, not how it was made | Bainbridge 1983; Bacchelli & Bird 2013 |
| 11 | "What you need to do" appears only when needed; the fewer items the better | To get readers to act, make the action simple and put all the information the action needs in one place | Rogers & Lasky-Fink 2023, *Writing for Busy Readers*, Principle 6 |
| 12 | Impact always lists Changes, Adds, Removes, Visible behavior | As a program keeps changing, its complexity grows unless work is done to reduce it; complexity accumulates bit by bit, and the worst case is not knowing what you don't know | Lehman 1980, *Proc. IEEE* 68(9), second law; Ousterhout 2018 |
| 13 | Each addition comes with a reason | In the code GitClear analyzed, copy-pasted lines outnumbered moved or refactored lines for the first time in 2024, as AI assistants spread; in the DORA 2024 survey, higher AI adoption went with lower delivery stability. Both findings are correlations, not causation | GitClear 2025; DORA 2024 |
| 14 | Visible behavior must include changes to security and permissions | Every observable behavior of a system will be depended on by somebody | Hyrum's Law (Winters et al. 2020) |
| 15 | The default rollback is reverting the commit; changes that cannot be rolled back must become decisions | Blast radius: the largest impact one bad change can cause; only changes that can be reverted as a whole are two-way doors | AWS Well-Architected REL10; Bohner & Arnold 1996; Bezos 2015 |
| 17 | The human doc does not record results; after execution, a completion report goes in the reply | A plan is a document for making decisions, not a status report; results should appear when the user needs them; closed-loop communication requires the side carrying out the work to report back on its own initiative | ISO 24495-1 Principles 1, 2; read-back and report-back practices in aviation and the military |
| 18 | The report checks each "When done" item with evidence, then gives 1 check the user can do | In METR's 2025 randomized controlled trial (16 experienced open-source developers, tools from early 2025), tasks took 19% longer with AI, yet the developers estimated afterward that they had been about 20% faster. METR has since marked this result as outdated, and this row takes only one point from it: how fast people feel and what is measured can differ. In the experiment by Perry et al., participants who used an AI assistant wrote less secure code, yet were more confident that it was secure. Keeping people in the loop prevents complacency. If people get only what automation leaves over, they are left with only the hardest monitoring tasks, and their skills decay | METR 2025 (updated 2026-02); Perry et al. 2023, CCS, arXiv 2211.03622; Parasuraman & Manzey 2010, *Human Factors* 52(3); Bainbridge 1983 |
| 19 | The report lists deviations beyond Impact first | Management by exception: report only what departs from the norm | Taylor 1903 (exception principle); Bittel 1964 |
| 20 | Usually 200 to 500 words, at most 900; readable, not compressed | On ordinary web pages, users have time to read at most about 28% of the words, and more likely 20% (web data, used here as an analogy); but incomplete sentences also make comprehension harder, so control length by cutting content, not by compressing sentences | Nielsen 2008 (How Little Do Users Read); ISO 24495-1 Principle 3 |
| 21 | Do not re-explain terms that were explained before | Expertise reversal effect: explanations that novices need are redundant for experts | Kalyuga et al. 2003 |
| 22 | Bold only for feature names and decision questions | Signaling principle: cue only the key points; too many cues lose their effect | Mayer & Moreno 2003 |
| 23 | STE writing: short sentences, complete sentences, a clear actor | Readers must be able to understand what they find: familiar words, clear and concise sentences, a consistent document | ASD-STE100 Issue 9 (2025); ISO 24495-1 Principle 3 (understandable) |
| 24 | Every sentence has a basis in the plan doc | Both documents come from the same source, so the human doc contains no promises outside the plan doc | Engineering convention; no specific theory |
